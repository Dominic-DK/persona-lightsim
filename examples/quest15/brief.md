# Quest15 제품 현실 브리프 (감사 완료 · 2026-08-25)

모든 문장은 `Projects/Quest15/`와 `Projects/TripRoll/supabase/` 코드·리소스로 검증했다.
검증 불가한 문장은 문장 끝에 **(추정)**을 붙였다. 태그 없는 문장은 코드 근거가 있다.

## 한 줄 정의

지금 있는 장소에서 10~15분짜리 작은 모험(퀘스트) 하나를 뽑아주는 iOS POC 앱. "어디 갈지"를 정해주는 앱이 아니라, 이미 있는 곳에서 바로 해볼 수 있는 작고 구체적인 행동을 준다. 앱스토어 미출시, 버전 0.1, 개발 Mac 로컬 서버 전용.

## 핵심 가설 (PRD)

사람들은 목적지 추천보다, 지금 있는 장소에서 바로 실행 가능한 작고 구체적인 행동을 받으면 더 쉽게 움직인다.

## 실제 화면 흐름 (구현됨)

홈에는 **독립된 두 개의 진입로**가 있다 (`Quest15HomeView.swift:53,344`).

- **A. "지금 여기에서 10개 추천"** — 현재 위치를 잡아 서버 `quest.recommend_quests(jsonb)`에 넘기고 후보 10개를 받는다. 첫 개는 즉시 수행 화면으로, 나머지는 "다음 장면"으로 넘긴다.
- **B. "퀘스트 뽑기"** — 위치 없이 장르·동행·기분·시선 4축을 직접 골라 번들 카탈로그에서 1개를 뽑는다.

추가 화면: **퀘스트 실험실**(개발자용 장소×인물×상황 비교기), **저장된 장면**(AI 변환 갤러리), 앱 첫 실행 온보딩 아트 덱(40장, `ArtCatalog.json`).

수행 화면(`QuestRunView.swift`)은 다음 구조다.

1. 퀘스트별 `durationMinutes`만큼 카운트다운이 돈다. **타이머는 아무것도 게이팅하지 않는다** — 0이 되어도 알림·자동완료·차단이 없고 완료 조건에도 들어가지 않는다 (`QuestRunView.swift:58-61,447-449`).
2. `attentionAction`(시선 행동, 6종) **완료 버튼을 눌러야 `twist`(반전)가 열리고**, 이 버튼이 완료의 필수 조건이다 (`:258-273,305-321,447-449`). 센서·위치·마이크 감시 없음 — 화면에 "수행 여부는 기록하거나 감시하지 않아요"라고 명시한다 (`:323`).
3. 흔적(residue)은 **사진 / 한 문장 / 단어 하나 / 남기지 않기 4개 모두 항상 선택 가능**하다 (`Quest15.swift:238-272`, `QuestRunView.swift:366`). 카탈로그가 주는 기본값은 `one_sentence` 174개 · `one_photo` 114개뿐이므로 사진이 기본인 경우는 40%다.
4. 사진을 남기면 **"이 사진을 그림으로 바꿔 받기"** 옵트인 토글이 뜬다 (아래 별도 항목).
5. 결과 카드를 텍스트로 공유(`ShareLink`)하고 UserDefaults에 로컬 저장한다.

## 데이터/기술 현실

- **번들 카탈로그: 288개 퀘스트 후보, 24개 장소, 94개 위치 노드, 28개 확장 dimension, 장소당 12개 변형 레이어.** 네 수치 모두 `QuestCatalog.json`(entryCount 288, placeId 24종 × 12개)·`ExperimentCatalog.json`(locationNodes 94, dimensions 28)에서 확인했고, 서버 `seed.sql`도 동일하다(quest_variants 288, location_nodes 94, dimension_options 28).
- **24개 장소는 대부분 관광지다.** 한국 9곳(경복궁·전주한옥마을·성산일출봉·해운대·광안리·사려니숲길·남해 지족·을지로 3가·서촌) 중 일상 도심은 을지로·서촌 2곳뿐이고, 나머지 15곳은 해외 관광지(시부야·기요미즈데라·교토 오하라·아이노쿠라·야쿠시마·사그라다 파밀리아·그라시아·할슈타트·이아·레인·플리트비체·페나 궁전·마테라·셰프샤우엔·우붓)다. **즉 카탈로그는 여행 사용에 크게 치우쳐 있다.**
- 후보 메타데이터: 필요 공간 affordance, 혼잡 민감도(high 144/medium 108/low 36), 안전 메모 3종(프라이버시·통행·사유지), 접근성 대체 경로, 긍정 회상 훅, 코호트·그룹 적합도, 도착 시점 슬롯.
- **소요 시간은 15분 고정이 아니다.** `durationMinutes`는 8·10·12·14·15·18분이 섞여 있고 **최빈값은 10분(110개), 15분은 63개뿐**이다. 홈 카피는 "15분 안팎"이라고 쓴다(`Quest15HomeView.swift:159`).
- 추천 계약: 위치 하나만 있어도 동작하고 `context`/`audience`/`intent`/`constraints`는 optional. 서버는 장소·건물·길·상황·분위기·목적·사람 축을 느슨하게 점수화한다. `limit`은 서버에서 **최소 10 / 최대 50으로 강제 클램프**된다(`20260806100000_quest15_recommendations.sql:106`). 서버 실패 시 좌표만으로 **동일 점수화 규칙의 로컬 fallback**이 돌고, 서버 결과가 10개에 못 미치면 로컬이 빈자리를 채운다(`QuestRecommendationService.swift:219-242`).
- OSM/Nominatim reverse geocoding으로 현재 좌표를 장소·건물·도로·구역 맥락으로 보강한다. 좌표 4자리 반올림 캐시 + 요청 간 최소 1.1초 간격의 저용량 POC 어댑터다(`QuestContextResolver.swift:34-49`).
- 같은 세션에서 퀘스트 ID·충돌 키(288개 전부 고유) 중복을 피한다. 다만 이 상태는 홈 화면의 `@State` 메모리 변수이므로 **앱을 다시 켜면 초기화된다**(`Quest15HomeView.swift:12-13`).
- 완료 결과는 공유 로컬 Supabase의 `quest.quest_runs`에 기록된다. 실패하면 화면에 `.failed`로 표시하고 로컬 저장만 남는다.

## 사진 → AI 그림 변환 (브리프 초안에 누락됐던 핵심 기능)

- 사진 흔적을 고르면 **옵트인(기본 꺼짐)** 토글로 사진을 그림으로 바꿔 받을 수 있다. 스타일은 서버 `quest.transform_styles`에서 받아온다.
- 동의 문구가 명시하는 것: 사진이 **기기를 떠나 변환 서버와 이미지 생성 모델로 전달되고, 원본은 14일 보관 후 삭제**된다(`QuestRunView.swift:116`). 14일은 DB에서 `source_expires_at default now() + interval '14 days'`로 강제되고, 클라이언트는 더 짧게만 바꿀 수 있다(`20260807000000_quest15_memory_transforms_hardening.sql:17,42-43`). 원본만 삭제되고 결과 그림과 행은 보존된다.
- 실행 주체는 개발 Mac의 로컬 파이썬 워커(`TripRoll/scripts/quest15_memory_worker.py`)가 `127.0.0.1:8787`의 codex app-server를 호출하는 구조다. **동시성 1, 1건당 40~90초**로 코드 주석에 실측이 적혀 있다. 호스팅 불가·확장 불가 구조다.
- 결과는 "저장된 장면" 갤러리에서 다시 본다. 실패 시 재시도 RPC가 있다.
- **변환은 `quest.quest_runs` 기록이 성공해야만 시작된다** — 로컬 서버가 안 닿으면 이 기능 전체가 죽는다(`QuestResultView.swift:105-131`).

## 과금 현실

- **과금 코드 전무.** StoreKit·인앱결제·구독·결제 SDK·가격 문자열이 레포 어디에도 없다(전수 grep 결과 `subscription` 3건은 모두 Realtime 구독 주석). 의존성은 supabase-swift 하나뿐(`project.yml`).
- **다만 "계정 없음"은 부정확하다.** Supabase **익명 인증**이 있고(`signInAnonymously`), 모든 완료 기록·업로드 사진이 익명 uid에 묶인다. 없는 것은 로그인·프로필·소셜 계정이다.
- 수익 모델은 전부 미검증 아이디어 단계: 장소별·도시별 퀘스트 팩, 크리에이터 퀘스트, 카페·전시·관광지 스폰서 퀘스트 (PRD "나중에 검증할 것" 목록).

## 알려진 실전 약점 (코드·실측)

1. **추천이 새 퀘스트를 만들어내지 않는다.** 서버든 로컬이든 288개 고정 카탈로그를 점수 정렬해 상위 N개를 돌려줄 뿐이고, **거리 필터가 기본으로 없다.** 시드 장소에서 멀면 거리 점수가 0으로 깎일 뿐 후보에서 빠지지 않으므로, 서울 밖·해외 임의 위치의 사용자도 "경복궁 · 정면이 숨긴 증거" 같은 **엉뚱한 장소명이 박힌 퀘스트 10개**를 받는다(`QuestRecommendationService.swift:24-51,81-85`; SQL은 `rank_number <= limit`만 자름). 최소 10개 반환 계약은 관련성이 아니라 완화로 달성된다.
2. **동행 선택이 후보를 전혀 좁히지 않는다.** 288개 전부가 `supportedCompanions = [solo, friends, date]`이고 `preferredCompanions`도 3개 전부다. 혼자/친구/데이트 선택은 +30 vs +15 가중치 차이일 뿐이다.
3. **장르·기분 조합 6개가 후보 0개다.** 48개 (동행×기분×장르) 조합 중 "느긋함+보물 사냥"이 아니라 **"느긋함+둘만의 작전"과 "웃음+보물 사냥"이 세 동행 모드 모두에서 0개**라 "남은 후보가 없어요" 에러가 뜬다. 분포도 심하게 치우쳐 있다: 장르는 비밀 조사 135 / 보물 사냥 73 / 평행세계 63 / **둘만의 작전 17**, 기분은 발견 224 / 기록 188 / 느긋함 135 / **웃음 46**, 시선은 작게 222 / 넓게 134 / 천천히 128 / **함께 46**. 즉 **데이트·웃음·함께 축이 구조적으로 얇다.**
4. **타이머가 장식이다.** 카운트다운이 완료 조건·알림·잠금 어디에도 연결돼 있지 않아 "15분"은 사실상 UI 카피다.
5. **장소 데이터의 29%가 공간 신호 수집 실패 상태다.** 24곳 중 7곳이 OSM 보강 실패(`spatialStatus:"error"` 노드 27/94), Wikimedia 사진 참조가 있는 장소는 9곳뿐(`research/README.md`). 좌표는 500m 반경 도형 중심점이라 실제 경계·보행 접근성과 분리돼 있다.
6. **런타임 적합성 검증 미구현.** 시간·날씨·혼잡·개방시간·접근성으로 후보를 거르는 단계가 없어 밤에 숲길 퀘스트가 나올 수 있다(PRD "나중에 검증할 것" 1번, 크리틱 원장 "다음 검증 순서" 2번).
7. **적대적 크리틱 루프가 아직 수렴하지 않았다.** 5라운드 47 claims, `exhausted=false`, 종료 조건(2회 연속 순신규 0건) 미충족. 최다 발견 축은 D1 장소 근거 15건, D5 다양성·안전 12건 (`research/ledgers/quest-content-r1.md`).
8. **출시 전 미결 법무 이슈가 남아 있다.** OSM **ODbL 개별 객체를 앱에 배포할지 집계만 내보낼지 미확정**, 리뷰·평점 데이터는 라이선스 확인된 API가 없어 `credential_check=not_performed`로 미수집. 리뷰 기반 추천은 발행하지 않는다.
9. **인프라가 출시 인프라가 아니다.** `Info.plist`의 `SUPABASE_URL`이 개발 Mac 사설 IP(`http://10.250.14.182:54321`)이고, 지도·소셜 피드·서버 기반 동시 사용자 배정이 없다.
10. **자동화된 테스트가 0건이다.** 레포에 테스트 파일도 테스트 타깃도 없다.
11. 스토리 프레임은 창작 장치이며 장소에 대한 사실 주장이 아니라고 README·연구 문서가 명시한다. 앱 화면 안에는 이 경계를 알리는 문구가 없어 사용자가 오해할 리스크가 있다 **(추정 — 실사용 관측 없음)**.

## 분석가에게 주는 포지셔닝 질문

- 이 제품은 "심심할 때 뭐하지" 앱인가, "여행지에서 뻔한 관광 탈출" 앱인가, "데이트 콘텐츠" 앱인가 — 어느 쐐기가 각 시장에서 먼저 서는가? (카탈로그는 22/24가 관광지, 데이트 장르는 17개뿐이라는 현재 편향을 감안할 것)
- 10~15분·자기신고·이야기 프레임이라는 장치가 어느 세그먼트에 매력이고 어느 세그먼트에 유치하게 느껴지는가?
- 사진→AI 그림 변환이 지불 의사의 주 동인이 될 수 있는가, 아니면 프라이버시 마찰(사진이 기기를 떠남·14일 보관)이 더 크게 작동하는가?
- 지불 의사가 생긴다면 어느 형태인가 (팩 구매/구독/스폰서 무료)?
