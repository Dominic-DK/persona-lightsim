# persona-lightsim

[English](README.md) | [한국어](README.ko.md) | **日本語** | [中文](README.zh.md)

[Claude Code](https://claude.com/claude-code)向けの軽量ペルソナ市場調査・シミュレーションハーネス。任意のプロダクトを**10か国の合成人口**(NVIDIA [Nemotron-Personas](https://huggingface.co/nvidia))に写像し、ユースケース分析・支払い意思の判定・バッチ判定による反応シミュレーション・再利用可能なペルソナカードを生成する — **ウェブアプリもシミュレーションサーバーも不要、データはわずか63MB。**

## AIに任せるセットアップ

Claude Code(または任意のコーディングエージェント)にそのまま貼り付ける:

```
https://github.com/Dominic-DK/persona-lightsim をセットアップして:
1. git clone https://github.com/Dominic-DK/persona-lightsim && cd persona-lightsim
2. python3 scripts/setup_data.py        # HuggingFaceから63MBのライトデータをダウンロード + pyarrow venv作成
3. セットアップが出力するスモークテストを実行して結果を見せて。
スキル文書の言語切替: python3 scripts/set_language.py ko (デフォルトは英語)。
```

以上。レポジトリをClaude Codeで開き、こう依頼するだけ:

- *「プロダクトXを10か国のペルソナに当ててユースケースと支払い意思を分析して」* → `persona-research`スキル(国別アナリストの並列ファンアウト)
- *「このブリーフで韓国100人の軽量シミュレーションを回してパックを作って」* → `persona-lightsim`スキル(バッチ判定 → mean-field 2次パス → カード蒸留 → sqliteパック)

## 使い方

レポジトリをClaude Codeで開き、一文で依頼すればいい。リクエストは4つのスロットからなる:

> **{プロダクト — そのコードや文書がどこにあるか}** → **{どの国}** → **{国ごとに何人}** → **{本当に知りたい問い}**

必須はプロダクトだけ。国は10か国全部、標本は国あたりn=1000、分析軸は「ユースケース + 支払い意思」がデフォルトになる。省いたスロットはデフォルトで埋めるか、一度だけ聞き返す。

### 市場全体のスキャン

[`examples/quest15/`](examples/quest15/) を生んだ依頼そのもの:

```
Projects/Quest15 は、今いる場所で10〜15分の小さな冒険をひとつ出すiOSアプリ。
レポジトリを読んで実際のコードからプロダクトブリーフを作り、10か国全部に
n=1000で当ててユースケースと支払い意思を分析して。
```

ハーネスはコードベースからブリーフを起草し、`persona-brief-auditor` がコード上の根拠を欠く文を削り、国ごとに約1,000人を標本抽出し、10人の国別アナリストを互いに見えない状態で並列に走らせ、市場横断で統合し、最終文書を書く前に敵対的クリティックへ渡す。通しでおよそ30分。

### 国を絞り、問いを研ぐ

```
TripRollのブリーフで韓国・日本・ベトナムだけ、各1000人。一般的なユースケースは
不要 — 旅行1回9,900ウォンの単発課金と月額サブスクのどちらが刺さるかを、
3市場それぞれで判定して。
```

軸を指定すると、全アナリストがその軸で標本を洗う。効く軸: 価格構造の比較、機能の優先順位、ポジショニングとメッセージ、離脱リスク、特定セグメントの実サイズ。

### セグメントに絞る

```
同じTripRollブリーフで韓国 + シンガポール、n=1000。複数人で旅行する層 —
友人・カップル・親族 — に焦点を当てて。結論を出す前に、そのセグメントが
各標本で実際に何%なのかを数えて。
```

### 軽量シミュレーションと再利用パック

```
監査済みのQuest15ブリーフで韓国100人の軽量シミュレーションを回して:
バッチ判定、意見再注入の2次パス、セグメントカード蒸留、sqliteパックのビルドまで。
1次・2次それぞれの受容と支払いの分布を見せて。
```

100人はパスあたりエージェント呼び出し4回(1回で25人を判定)、2パスで8回、その間に決定的な集計が1段入る。得られるのは個人ごとの受容/支払い/反論の判定、1次パスの意見要約を2次に再注入した結果、標本原文の引用を伴うセグメントカード、そしてクエリ可能なsqliteパック。

### まだレポジトリがない場合

```
コードはまだない、アイデア段階。[何をするものか、誰のためか、いくら取るか、
具体的な事実を3〜4文。] これでブリーフを作って、検証できないものは全部
「仮定」と印を付けて、フランスとベルギーをn=1000でユースケースと価格。
```

この場合、監査者が突き合わせるコードがないので文は仮定として印付けされ、アナリストも仮定として扱う。ブリーフが分析全体の天井になる — 曖昧に入れれば曖昧に出てくる。

### 追加依頼

どちらのスキルも既存の `_workspace/` を検出し、変わった部分だけ回し直す:

- *「韓国レポートだけやり直して、今度はひとり旅の観点で」*
- *「既存のランにインドを追加して」*
- *「ブリーフが変わった — 広告付き無料モデルになった。判定だけ更新して、標本とカードの不変部は残して」*
- *「カードを蒸留し直して、1枚あたり根拠引用3つ以上で」*
- *「パックに支払いセグメントを問い合わせて」* — パックが答えるクエリは `payment_segments`、`top_objections`、`card_evidence --card <card_id>`

### 「条件」が実際に適用される場所

サンプラーが取る引数は `--countries`、`--n`、`--seed` だけで、人口統計フィルタは存在しない。したがって「30代女性だけ」「複数人で旅行する層」といった条件は抽出ではなく**分析段階で**適用される: キーワードと人口統計のスクリーニングで絞り、代表標本の中での実カウントをレポートが明示する。たいていはこれが欲しい結果だ — 事前に絞ったプール内の比率ではなく、人口内の比率なので。

本当にハードフィルタが要るなら明示的に頼めばいい(「30〜39歳だけ残して分析して」)。エージェントが標本JSONLを後処理でフィルタする。ただしそのレポートの%はフィルタ後プール基準になり、全標本ランとは直接比較できない。

### ディスクに残るもの

| パス | 内容 |
|---|---|
| `_workspace/persona-research/` | ブリーフ、国別標本、国別レポート、クリティック所見 — 監査証跡 |
| `docs/research/persona-{product}-{YYYY-MM}.md` | 最終の市場横断ドキュメント |
| `_workspace/persona-lightsim/` | スライス、1次・2次の判定、集計、`cards.json` |
| `_workspace/persona-lightsim/persona_pack.sqlite3` | クエリ可能なパック(+ `_nodes.json` エクスポート) |

標本はシードから再現できるため、再実行時は既定で引き直さず既存標本を再利用する。

## 構成

| 要素 | 役割 |
|---|---|
| `.claude/skills/persona-research` | オーケストレーター: ブリーフ監査 → サンプリング → 国別分析ファンアウト → 統合 → QA |
| `.claude/skills/persona-country-analysis` | 単位方法論: 実カウントスクリーニング → 精読 → 7セクションレポート |
| `.claude/skills/persona-lightsim` | 対話なしシミュレーション: バッチ判定(1呼び出し=25人) → 決定的集計 → 世論再注入2次パス → セグメントカード → ローカルパック |
| `.claude/agents/persona-*` (5種) | brief-auditor / country-analyst / synthesis-critic / batch-judge / distiller |
| `scripts/setup_data.py` | ライトデータのダウンロード(sha256固定マニフェスト) + venv構成 |
| `scripts/set_language.py` | アクティブなスキル・エージェント文書を`en`/`ko`で切替 |

元ハーネスでのパイプライン全体の実測値: バッチ判定スキーマ有効99/99、2次パスの意見変化率24.2%(0%でも100%でもない — mean-field再注入が実際に機能することを実証)、カードの根拠引用39/39をサンプル原文と照合検証。

## データ

`scripts/setup_data.py`が取得するのは**ライトパック** — [`dominicDK94/nemotron-personas-lite`](https://huggingface.co/datasets/dominicDK94/nemotron-personas-lite) — NVIDIA Nemotron-Personas(CC-BY-4.0)の派生再配布版:

- 10か国: ベルギー・ブラジル・エルサルバドル・フランス・インド・日本・韓国・シンガポール・米国・ベトナム
- 国あたり10,000人、原本0.1M~1.2Mからシード42固定抽出
- 26カラム中ハーネスが読む15カラムのみ保持、長い叙述フィールドは300~400字にトリム
- 原本のシャード構造を保存(ベルギーの言語クォータ、インドの英語のみ) — サンプラーはライト/フルデータで無修正で動作
- **合計~63MB**(原本は~24GB)

トリムなしのフルデータが必要な場合はNVIDIAの原本をHuggingFaceから取得し、環境変数で指定する:

```bash
export NEMOTRON_PERSONAS_BASE=/path/to/full-data   # nemotron-personas-*/ の親ディレクトリ
```

## 注意と限界

- ペルソナは合成された人口構成であり行動ログではない。すべてのスキルが結論を**「方向性の仮説」**として書き、実験での検証を強制する。
- 軽量シミュレーションは**mean-field近似**: 同調・硬化といった1次の社会効果は捉えるが、エコーチェンバー・伝播力学といった構造効果は範囲外。
- エージェント定義のデフォルトは`model: opus` — `.claude/agents/*.md`で変更可能。
